# 2026-08-08 SID 握手安全漏洞修复与健壮性升级

## 背景

上一轮已完成 SID 会话密钥握手安全的基础实现（per-session sid、鼠标心跳、fail_count 阈值轮换、root 豁免）。
运行全量测试时发现 `TestHandshake.test_repeated_failures_trigger_rotation` 断言失败：sid 被轮换后，
心跳端点 `/api/auth/handshake` 仍返回 `code=0`（成功），未返回预期的 `4034`。

根因：`handshake_heartbeat` 仅调用 `update_handshake(sid)` 更新活跃时间戳，
`update_handshake` 内部对已轮换 sid 静默跳过更新（`if s is not None and not s.get("rotated")`），
但端点仍返回成功响应。攻击者可利用此漏洞对已吊销 sid 持续发送心跳维持会话。

## 修复过程

### 阶段一：修复心跳端点 sid 轮换检测

1. `app/handshake.py` 新增 `is_sid_rotated(sid) -> bool` 辅助函数。
2. `app/routers/auth.py` `handshake_heartbeat` 在调用 `update_handshake` 前先检测 sid 是否已轮换，
   若已轮换则抛出 `BizError(4034, "会话密钥已因安全原因轮换，请重新登录")`。
3. 修复 `tests/test_security_hardening.py` `test_image_compression_and_original_point_gate`：
   测试 POST `/api/tasks` 未携带 `X-SID` 头，被 `require_handshake` 守卫拦截返回 4033。
   补充 `X-SID` 头与一次握手心跳调用。
4. 全量测试 61 项全部通过。

### 阶段二：故障检测子 AGENT 健壮性审查

调用 search 子 AGENT 对 SID 握手安全系统做全面审查，输出结构化报告，
发现 1 项 Critical、5 项 Medium、6 项 Low、4 项 Suggestion。

### 阶段三：修复审查发现的安全隐患

#### C1（Critical）：配置项 DoS

**问题**：`threshold_handshake_timeout`/`threshold_handshake_fail_limit` 不在 `DEFAULT_THRESHOLDS` 中
（只能直接改 DB，绕过 API 校验），且 `update_thresholds` 仅校验 `num < 0`，允许设为 0。
若设为 0：`now - last <= 0` 恒为 False → 全站非 root 用户每次写请求都判定握手失败 →
失败计数达阈值 → 轮换全部 sid → 全站无法发言（DoS）。

**修复**：
- `app/database.py`：将两个握手阈值纳入 `DEFAULT_THRESHOLDS`；新增 `THRESHOLD_MIN_VALUES` 字典
  定义硬下限（timeout≥10、fail_limit≥1、ip_default_limit≥1 等）。
- `app/routers/root.py`：`update_thresholds` 在非负整数校验后追加硬下限校验。
- `app/handshake.py`：`_get_timeout`/`_get_fail_limit` 强制 `max(val, hard_min)` 兜底。
- 三重防护：API 校验 + 服务端兜底 + 默认值。

#### M1：心跳端点不校验 sid 归属

**问题**：`handshake_heartbeat` 仅依赖 `get_current_user` 鉴别身份，但 `is_sid_rotated`/`update_handshake`
不校验 sid 是否属于当前用户。攻击者可用自身令牌 + 受害者 sid 持续刷新受害者 sid 的活跃时间，
使受害者 sid 永不超时，绕过 `_maybe_cleanup` 回收。

**修复**：`handshake.py` 新增 `update_handshake_checked(sid, user_id) -> (status, now)`，
原子地校验 sid 归属 + 轮换状态 + 更新活跃时间（避免 TOCTOU）。`auth.py` 心跳端点改用该函数：
sid 不属于当前用户 → 4033，sid 已轮换 → 4034，校验通过 → 更新。

#### M2：登出不校验 sid 归属

**问题**：`logout` 接收 `X-SID` 后直接 `clear_handshake(sid)`，不校验归属。
攻击者可用自身令牌 + 受害者 sid 清除受害者会话，迫使受害者重新登录（DoS）。

**修复**：`handshake.py` 新增 `clear_handshake_for_user(sid, user_id) -> bool`，
仅在 sid 属于当前用户时清除，同时清 `_user_fails`。`auth.py` logout 改用该函数。

#### M4：多 sid 并存未及时失效

**问题**：`_issue_session` 每次 login/refresh 签发新 sid，旧 sid 仍留在 `_sessions` 中且
`rotated=False`，直到 `_maybe_cleanup` 在 3 倍超时（约 180s）后才回收。期间旧 sid 仍可被
`require_handshake` 接受，形成复用窗口（令牌窃取后旧 sid 可继续使用 180s）。

**修复**：`handshake.py` 新增 `invalidate_user_sids(user_id)` 静默失效该用户所有旧 sid
（标记 `rotated=True` 但不写系统通知，避免登录轰炸）。`auth.py` `_issue_session` 签发新 sid 前调用。

#### M5：失败计数器内存放大

**问题**：`_record_user_fail` 每次调用 `append(now)`，窗口内记录数量无上限。
高频失败请求可使单用户 `_user_fails` 列表膨胀至数十万条。

**修复**：`handshake.py` `_record_user_fail` 增加单用户上限 `_FAIL_LIST_MAX=200`，
超过则保留最近记录；同时在失败路径调用 `_maybe_cleanup` 触发周期性清理。

#### L1：状态端点不校验 sid 归属

**修复**：`handshake.py` 新增 `get_handshake_status_for_user(sid, user_id)`，
sid 不属于当前用户时返回空状态（防信息泄露）。`auth.py` `handshake_status` 改用该函数。

#### L2：TOCTOU

**修复**：`update_handshake_checked` 将"检查轮换 + 检查归属 + 更新活跃时间"合并为单一临界区操作。

#### L4：登出不清理失败计数

**修复**：`clear_handshake_for_user` 在清除 sid 时同时 `_user_fails.pop(user_id, None)`。

#### L5：前端后台标签心跳恢复迟缓

**问题**：浏览器对后台标签页的 `setInterval` 会节流至最低 1 次/分钟。用户切到后台 >60s 后
心跳停止 → sid 超时 → 切回前台时下一次写操作收到 4033。

**修复**：`static/common.js` `HandshakeManager.init` 新增 `document.visibilitychange`
（切回前台立即补发心跳）与 `window.focus`（窗口获焦补发心跳）监听。

## 未修复项（已记录，按优先级后续处理）

- **M3（鼠标活动为客户端自证）**：设计固有局限，脚本化客户端只需每 <60s 调用一次 `/auth/handshake`
  即可绕过。已在 Design.md 中澄清握手机制定位为"会话活跃度检测"而非"绝对真人验证"。
  根本性建议：增加鼠标轨迹指纹签名 + 心跳速率限制，但会增加客户端复杂度，暂不实现。
- **L3（require_handshake 锁释放与 _record_user_fail 间的 TOCTOU）**：良性竞态，
  `rotate_user_sids` 对已轮换 sid 是幂等的，仅可能重复写系统通知，无安全后果。
- **L6（_maybe_cleanup 在锁内调用 _get_timeout 触发 DB I/O）**：每 300s 才执行一次，
  高并发下可能造成短暂延迟尖峰，可接受。
- **S1（root 豁免 + 7 天 access token）**：root 双因素登录已保障安全，建议未来为 root 配置
  更短的 access token TTL，暂不实现。
- **S2（已轮换 sid 主动回收）**：当前依赖 `_maybe_cleanup` 按超时回收，可在轮换后 5 分钟主动删除，
  内存优化项，暂不实现。
- **S3（_by_user 回退路径）**：前端始终携带 `X-SID`，回退路径仅为兼容遗留，可考虑废弃。
- **S4（失败计数器连坐设计）**：当前按 user_id 维度计数，多设备场景下某设备触发失败会轮换全部 sid。
  偏保守安全设计，保留并在文档说明。
