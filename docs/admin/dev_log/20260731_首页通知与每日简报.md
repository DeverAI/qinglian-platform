# 2026-07-31 首页通知与每日简报轮

## 目标

增加首页通知功能，设计符合"青联"立意的亮丽首页，包含图标、国家新法规政策 AI 搜索摘要（无新内容时显示历史上的今天）。参考独立项目剥离的功能，避免全部照搬。

## 实现内容

### 后端

1. **新建 `app/routers/notify.py`**：首页通知与每日简报路由模块
   - `GET /api/notify/briefing`：获取今日简报，优先读缓存，缓存不存在则现场生成
   - `GET /api/notify/messages`：返回最近 N 条系统通知（含 unread 未读计数）
   - `POST /api/notify/messages/read`：全部标记已读
   - `DELETE /api/notify/messages/{id}`：单条删除（含非法 id 与不存在 id 校验）
   - `DELETE /api/notify/messages`：清空全部
   - `add_system_message`：工具函数供其他模块写入通知
   - `_generate_daily_briefing`：调用 AI 联网搜索近 7 日合规/未成年人保护/数据安全新法规政策，生成 200 字内摘要；无新内容降级为"历史上的今天"；失败降级为静态兜底；落盘缓存到 `storage/briefings/briefing_YYYY-MM-DD.json`，并同步写入 `system_messages` 表

2. **修改 `app/main.py`**：
   - 挂载 notify 路由（`prefix=/api/notify`）
   - lifespan 启动时同步触发一次简报生成（AI 未配置时走静态兜底，失败仅写 `Err.log`）

3. **修改 `app/routers/root.py`**：`SERVICE_NAMES` 增加 `notify`，Root 可动态开关通知服务

4. **修改 `app/database.py`**：新增 `system_messages` 表及索引

5. **修改 `app/config.py`**：新增 `BRIEFING_DIR` 路径配置，支持 `QLKIMI_BRIEFING_DIR` 环境变量便于测试隔离

## 关键问题与修复

### 问题1：notify 路由未注册（测试 KeyError: 'code'）

**现象**：测试中 `/api/notify/briefing` 与 `/messages` 接口返回 404，响应无 `code` 字段。

**排查过程**：
- 直接 `import notify.router` 路由正常（5 条路由均存在）
- 通过 `app.main` 加载时，`app.routes` 中只有 11 个 `_IncludedRouter`，notify 缺失
- 发现 `main` 模块没有 `notify` 变量
- 关键发现：磁盘上的 `main.py` 实际不包含 notify 代码（183 行），但 Read/Edit 工具显示的是缓存版本（188 行含 notify）

**根因**：Read/Edit 工具基于缓存操作，修改未写入磁盘。

**修复**：用 Python 脚本（通过 PowerShell here-string 创建临时 .py 文件）直接读取磁盘文件、替换内容、写回磁盘，成功插入 notify 路由挂载代码。

### 问题2：通知列表为空（assert 0 >= 1）

**现象**：路由注册成功后，briefing 接口返回 `code: 0`，但 `system_messages` 表为空。

**排查过程**：
- 直接查数据库发现 `system_messages count: 0`
- 但 `briefing_2026-07-31.json` 缓存文件已生成
- 发现 `_generate_daily_briefing` 在 AI 未配置分支中直接 return，跳过了 `add_system_message` 调用

**根因**：AI 未配置分支（`STATIC_FALLBACK`）没有调用 `_notify_briefing`。

**修复**：
- 新增 `_notify_briefing` 辅助函数，统一处理简报写入 `system_messages` 的逻辑
- AI 未配置分支调用 `_notify_briefing(STATIC_FALLBACK)`
- AI 成功分支重构为调用 `_notify_briefing(data)`

### 问题3：历史缓存污染测试

**现象**：修复问题2后测试仍失败，`system_messages` 仍为空。

**排查过程**：
- debug 发现 `briefing_2026-07-31.json` 缓存文件存在于项目 `storage/briefings/` 目录
- `_generate_daily_briefing` 发现缓存存在就直接 return，跳过了 `_notify_briefing`

**根因**：`BRIEFING_DIR` 使用项目固定路径，历史 debug 运行生成的缓存文件污染了测试环境。

**修复**：
- `config.py` 中 `BRIEFING_DIR` 支持 `QLKIMI_BRIEFING_DIR` 环境变量
- `conftest.py` 中设置 `QLKIMI_BRIEFING_DIR` 为临时目录，实现测试隔离
- 删除项目 `storage/briefings/` 下的历史缓存文件

## 经验教训

1. **工具缓存问题**：Read/Edit 工具可能基于缓存操作，修改未写入磁盘。当修改似乎不生效时，用 Python 脚本直接读写磁盘文件验证。
2. **测试隔离**：所有文件路径配置都应支持环境变量，避免历史缓存或状态污染测试环境。
3. **分支覆盖**：所有降级/兜底分支都应完整执行副作用（如写入通知），不能直接 return。
