## 完成内容

### 1. 环境与错误日志治理

- **debug_reg.py**
  - 使用 `with TestClient(app) as client:` 触发 lifespan，保证测试环境数据库表初始化。
- **Err.log**
  - 读取历史记录（旧调试脚本导致的 `no such table: users`），确认非生产缺陷后清空。
- **FreqErr.md（新增）**
  - 记录本轮及历史出现的两类常见错误：
    - `sqlite3.Row` 无 `.get()` 方法；
    - 跨模块常量（如 `ROOT_EMAIL`）未导入。

### 2. 修复测试暴露的运行时错误

- **app/security.py**
  - `_check_bans` 中 `row.get("role")` 改为 `row["role"]`，修复登录/Token 校验 500 错误。

- **app/routers/admin.py**
  - 补充从 `..config` 导入 `ROOT_EMAIL`，修复邮箱封禁 500 错误。
  - 任务打码接口：文件删除操作从事务内移到事务提交成功后执行，避免 DB 回滚时原图已被删除导致引用断裂。
  - 任务打码接口：增加空 `images` 列表校验。

### 3. 修复 AGENT 复检发现的 Critical/High 问题

- **app/main.py**
  - `_ensure_root_user` 使用 `config.ROOT_EMAIL` 作为 Root 账号邮箱，与 `auth.py` 的 Root 双因素登录保持一致，修复默认配置下 Root 无法登录的问题。

- **app/routers/forum.py**
  - `create_post` 增加板块状态校验（仅 `open` 可发帖）、禁止向根分类（`parent_id IS NULL`）发帖、标题/内容去空后非空校验。
  - `create_reply` 增加回复内容去空后非空校验。

- **app/database.py + app/common.py**
  - `point_logs` 表新增 `UNIQUE(user_id, ref_type, ref_id, reason)` 约束与对应唯一索引。
  - `add_points` 捕获 `sqlite3.IntegrityError` 并静默跳过，保证并发或重复调用时积分只发放一次。

### 4. 验证结果

- 运行 `python -m pytest tests/test_api.py -v`：31 个测试全部通过，无回归。
- `Err.log` 检查为空，无新增运行时错误。
- 子 AGENT 最终复检：Critical/High 问题已修复，剩余中低风险项（如 token 黑名单、全局速率限制、最后 root 保护等）按业务优先级后续处理。
