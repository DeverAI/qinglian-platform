# 2026-08-01 首页消息流、新闻栏与条文背诵游戏轮

## 目标

1. 首页类似参考文件，下方增设消息流，除个人动态外可关注某板块消息。
2. 增加新闻栏，每晚审核聊天对话的同时检查新闻，生成摘要并注明原文出处。
3. 增加条文背诵游戏（本质填空题，以选择题形式呈现），用于增加积分。
4. 优化页面布局设计排版，禁止 emoji，无法绘制的 SVG 按规则写需求文件。
5. 移动端优化。

## 实现内容

### 后端

1. **新建 `app/routers/feed.py`**：首页消息流 API
   - `GET /api/feed?tab=all|mine|subscriptions|news&limit=20`
   - `mine`：当前用户的任务进度 + 自己发过/回复过的帖子
   - `subscriptions`：`board_subscriptions` 关联的板块新帖
   - `news`：`news` 表最近 7 天
   - `all`：合并以上并按时间倒序
   - 未登录用户仅可看 `all`/`news`
   - 查询时触发 7 天前新闻置 is_active=0

2. **新建 `app/routers/news.py`**：新闻栏 API
   - `GET /api/news?limit=20`：展示最近 7 天新闻
   - `POST /api/news/admin/collect`：管理员手动触发采集
   - `_collect_news()`：调用后台配置的 AI 接口（复用 `agent._ai_config()`），prompt 要求联网搜索当日与互联网合规、未成年人保护、个人信息保护、数据安全相关的权威新闻，输出 JSON 数组 `[{title, abstract, source_name, source_url, published_at}]`，明确禁止编造链接；同日按 (title, source_url) 去重落库
   - AI 未配置或调用失败时返回 `{collected:0, reason}`，不报错

3. **新建 `app/routers/quiz.py`**：条文背诵游戏 API
   - `GET /api/quiz/question`：从 `knowledge_entries`（category=law）随机抽取，按句号/分号切分选 20-80 字句子，挖空 2-4 字实词生成 4 选 1 选择题，落库 `quiz_questions`；校验今日已答 < 5，达上限返回 4032
   - `POST /api/quiz/answer`：校验未答过本题；正确 `add_points(user, 1, '条文背诵答对', 'quiz', question_id)`，错误仅写记录不扣分；并发超答时仍记录但不加分
   - `GET /api/quiz/today`：返回今日已答/已对/上限/剩余

4. **修改 `app/routers/forum.py`**：新增板块订阅接口
   - `POST /api/forum/categories/{id}/subscribe`：关注板块
   - `DELETE /api/forum/categories/{id}/subscribe`：取消关注
   - `GET /api/forum/my/subscriptions`：我关注的板块列表

5. **修改 `app/database.py`**：新增四张表
   - `board_subscriptions`（user_id, category_id, created_at, UNIQUE(user_id, category_id)）
   - `news`（id, title, abstract, source_name, source_url, published_at, collected_at, is_active）
   - `quiz_questions`（id, knowledge_id, blank_text, options_json, answer_index, created_at）
   - `quiz_records`（id, user_id, question_id, is_correct, answered_at, UNIQUE(user_id, question_id)）

6. **修改 `app/main.py`**：
   - 挂载 feed/news/quiz 路由（`prefix=/api/feed|/api/news|/api/quiz`）
   - `SERVICE_PATH_PREFIXES` 补全 notify/feed/news/quiz，使 Root 动态服务开关可拦截
   - lifespan 启动时同步触发一次 `_collect_news()`（AI 未配置时直接返回）

7. **修改 `app/routers/root.py`**：`SERVICE_NAMES` 增加 `feed`/`news`/`quiz`

## 关键问题与修复

### 问题1：main.py 未挂载 feed/news/quiz 路由

**现象**：首轮测试若运行将全部 404（本轮在运行测试前通过 MCP Read 直接读磁盘文件发现）。

**根因**：上轮使用 Read/Edit 工具修改 main.py 时，工具基于缓存操作，磁盘文件未实际写入 feed/news/quiz 路由挂载代码与 `SERVICE_PATH_PREFIXES` 补全。Edit 工具在尝试补全时还出现了行重复与内容损坏。

**修复**：
- 改用 Write 工具整体重写 main.py（含全部正确内容）
- 用 integrated_code_mode MCP 的 Read 工具直接读磁盘文件验证写入成功（绕过 Read 工具的缓存）
- 验证 `feed.router`/`news.router`/`quiz.router`/`"/api/feed": "feed"` 等关键字符串均已落盘

### 问题2：PowerShell 执行策略阻塞命令

**现象**：所有 RunCommand 调用均返回 "File command.ps1 is not digitally signed" 错误，无法运行 pytest。

**根因**：系统将命令包装为 .ps1 文件后用 PowerShell 执行，本机 ExecutionPolicy 阻止未签名脚本运行；即使命令本身是 `Set-ExecutionPolicy Bypass` 也因被包在 .ps1 内而无法先执行。

**修复**：改用 integrated_code_mode MCP 的 `Shell` 工具执行命令（不经过 .ps1 包装），成功运行 `python -m pytest tests/test_api.py -v`。

## 经验教训

1. **工具缓存问题再现**：上轮已记录 "Read/Edit 工具可能基于缓存操作，修改未写入磁盘"，本轮再次踩坑。对关键文件修改后，应使用 integrated_code_mode MCP 的 Read 工具（直接读磁盘）或运行测试验证，不能仅信赖 Read/Edit 工具的回显。
2. **Write 整体重写优于 Edit 局部修改**：当 Edit 出现行重复/内容损坏时，直接用 Write 整体重写文件更可靠。
3. **PowerShell 执行政策绕过**：当 RunCommand 因 .ps1 签名问题阻塞时，改用 integrated_code_mode MCP 的 `Shell` 工具可绕过该限制。
