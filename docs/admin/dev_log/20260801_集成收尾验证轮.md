## 阶段3：子AGENT 全局故障检测

### 调用上下文故障检测专员
以"刁难"视角审查 content_guard.py、board_lifecycle.py、ai_review.py、root.py、forum.py、emails.py 六模块。

### 发现并修复的问题

| 级别 | 模块 | 问题 | 修复 |
|------|------|------|------|
| High | content_guard.py | check_duplicate 表名拼接无白名单，有SQL注入风险 | 添加 `_DUPLICATE_TABLES` 白名单，非法表名抛 ValueError |
| High | content_guard.py | auto_long_text_to_txt 无路径穿越保护 | 添加 `.resolve()` 校验，确保文件在 UPLOAD_DIR 内 |
| High | ai_review.py | run_ai_initial_review 异常时默认 pass（不安全） | 改为默认 reject，异常时退回 |
| High | ai_review.py | _parse_json_response 无 try/except，解析失败抛裸异常 | 添加 try/except 捕获 JSONDecodeError，记录日志并抛 BizError |
| High | forum.py | board_claims 认领无写锁，并发抢领可能数据不一致 | 添加 `BEGIN IMMEDIATE` 获取写锁 |
| Medium | emails.py | submit-review 状态竞争条件（UPDATE 无 WHERE 条件校验） | 添加 `WHERE status IN ('draft','failed')` 条件 + changes() 二次校验 |

### 未修复的 Medium/Low 项（按优先级暂缓）
- `run_daily_lifecycle` 并发锁（仅启动时调用一次，风险低）
- `run_daily_patrol` 分页（后续数据量大时优化）
- `update_thresholds` 值范围校验（管理员接口，风险低）
- `admin_review_email` 状态竞争条件（已通过 WHERE 软保护）
